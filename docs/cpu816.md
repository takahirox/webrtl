# 65C816 machine-code example (#16)

Choose **65C816 CPU · machine-code ROM test**, click **Load example (replaces
project)**, then **Compile**. The twelve editable `.v` files compile through
the existing browser Yosys → CXXRTL → Clang/LLD pipeline into fresh Wasm.
No CPU binary, prerecorded trace, JavaScript instruction interpreter, game ROM,
VHDL compiler, or compilation service is involved. The static build only copies
source and tools, including when served from `/webrtl/`.

**Step** advances one board/CPU clock. **Run** requests 256-clock batches at a
target 10,000 clocks/s. The unmodified program displays **PASS** at clock 37.
**Pause** stops scheduling; **Reset** pauses, resets CPU, RAM, mailbox, timeout
and trace, and restarts the reset sequence on the next Step/Run. Compilation
also starts a fresh reset model. Editing discards the previous circuit; a failed
compile leaves controls disabled until corrected and recompiled. The CPU result
is `0` while running, `1` for PASS, `255` for FAIL. The board freezes CPU `CE`
after a result; Run can still advance board clock counts until paused.

Expand **CPU bus trace** to inspect sampled address, direction, byte, VPA and
VDA. These are registered in RTL from the bus consumed at each rising edge.
The adapter transports them without decoding instructions or deciding success.

## Core, license and HDL adaptations

The core is **P65C816**, by srg320, using Alan Steremberg's existing
[SystemVerilog conversion for Apple-IIgs_MiSTer](https://github.com/MiSTer-devel/Apple-IIgs_MiSTer/tree/9adbba8622f378253765b7d438b6cbcc4d03fc57/rtl/65C816),
pinned to **9adbba8622f378253765b7d438b6cbcc4d03fc57**. It originates in
[SNES_MiSTer's VHDL CPU](https://github.com/MiSTer-devel/SNES_MiSTer/tree/master/rtl/CPU).
The upstream provenance and changes are preserved verbatim in
[UPSTREAM.md](../examples/cpu816/UPSTREAM.md). This is the existing RTL CPU,
including its opcode/microinstruction sequencer, registers, address generator
and ALU, rather than a replacement bus sequencer.

The CPU is **GPL-3.0-or-later**; copyright/license headers and the
[full license](../examples/cpu816/LICENSE) are retained. The three new board,
memory and ROM sources are provided under that license too. The ROM is an
original, freely redistributable test program. Redistributing a compiled circuit
containing this core requires complying with its GPL terms, including providing
corresponding source. The static artifact ships all adapted HDL and the C++/JS
build adapter; the repository supplies the adaptation script and build/test
instructions. The app's other examples and toolchain keep their existing notices.

The adaptation is reproducible with
[scripts/adapt_cpu816.py](../scripts/adapt_cpu816.py): pass the `rtl/65C816`
directory from the pinned checkout. This is a maintenance tool, never run by the
static build or browser. Changes from that revision are limited to:

- `.sv` → `.v` filenames for the current project importer (still parsed with
  `read_verilog -sv`). The package file must precede modules using its types;
  the example's source order does so.
- Package-qualified packed-struct type names instead of wildcard imports.
- The unpacked constant array initializers `M_TAB` and `ALU_TAB` become case
  functions, since the current Yosys frontend does not accept that initializer
  syntax. Every defined bit is retained, including all opcodes. Undefined table
  entries remain `x` through the default arm. There is no program-specific
  pruning, microcode change, register modification or instruction substitution.
- A short adaptation comment; upstream implementation/comments otherwise remain.

The retained core implements 65C816 emulation/native modes, 8/16-bit register
widths, binary/decimal arithmetic, long addressing, stack and interrupt logic.
This integration validates the documented emulation-mode program only; it does
not establish whole-ISA correctness, interrupt correctness or cycle-perfect
hardware compatibility. Its instruction encodings/reset vector follow the
[WDC datasheet](https://www.westerndesigncenter.com/wdc/documentation/w65c816s.pdf).
The board ties IRQ/NMI/ABORT inactive and RDY high. There is no external ROM loader,
interrupt device, stack RAM or general CPU debugger in this example.

## Board bus and memory map

[cpu816-test.v](../examples/cpu816/cpu816-test.v) connects the core's **24-bit
`A_OUT`**, `D_IN`, `D_OUT`, **active-low `WE`**, VPA and VDA to
[cpu816-memory.v](../examples/cpu816/cpu816-memory.v). A transfer is valid only
while CE is enabled and `VPA || VDA`; a write additionally requires `!WE`.
Opcode fetches assert both VPA/VDA; operand fetches assert VPA, and data/vector
cycles assert VDA. Reads are combinational and sampled on a rising edge;
RAM/mailbox writes commit on that edge. This board inserts no wait states.

| 24-bit address | Device/behavior |
| --- | --- |
| `$00:8000–$00:FFFF` | Sparse inline ROM, read only; unspecified bytes are STP (`DB`) |
| `$00:FFFC–$00:FFFD` | Emulation reset vector, little-endian `$8000` |
| `$01:0000–$01:000F` | 16 bytes of reset-cleared RAM, full address decoded |
| `$00:2000` | Write-only result mailbox: `01` → PASS; any other byte → FAIL |
| All other addresses | Reads return `FF`; writes ignored |

The board's active-high synchronous reset clears its own state/RAM and drives
the CPU's active-low asynchronous `RST_N`. One adapter reset clock initializes
both, followed by deassertion with no extra counted clocks. The upstream CPU
then performs its reset microsequence: in this integration there is an initial
bus read at zero, followed by stack-like writes to `$00:0100`, `$00:01FF`,
`$00:01FE`, then vector reads at clocks 6 and 7. Those writes hit unmapped space
and are ignored. These are **observations of this core**, including its reset
quirks, not claims about physical W65C816 reset waveforms. First opcode fetch
is `$00:8000` at clock 8. Reset remains deterministic before/after RAM accesses
and after either outcome.

Unlike the #14 fixed bus master, the CPU chooses its address, read/write and
valid phases from instruction execution. The earlier #14 valid/write protocol
is not a SNES bus specification. Neither this combinational board bus nor the
core's reset sequence is claimed to be cycle-perfect SNES/5A22 timing. There
are no console devices, bank mirrors, cartridge mapping or DRAM refresh.

## Test ROM and expected execution

[cpu816-rom.v](../examples/cpu816/cpu816-rom.v) is the source of truth. Reset
enters emulation mode (`E=1`, `M=X=1`); CLC/CLD establish binary addition without
carry. The program deliberately discards A before RAM readback.

| PC (bank 00) | Bytes | Instruction/purpose |
| --- | --- | --- |
| `8000` | `18` | CLC |
| `8001` | `D8` | CLD |
| `8002` | `A9 12` | LDA #$12 |
| `8004` | `69 34` | ADC #$34 → A=$46 |
| `8006` | `8F 00 00 01` | STA $010000, exercises the bank address byte |
| `800A` | `A9 00` | LDA #0 |
| `800C` | `AF 00 00 01` | LDA $010000 → A=$46 from RAM |
| `8010` | `C9 46` | CMP #$46 → Z=1 |
| `8012` | `D0 06` | BNE $801A; normally not taken |
| `8014` | `A9 01` | LDA #1 |
| `8016` | `8D 00 20` | STA $2000 → PASS |
| `8019` | `DB` | STP, fallback; CE freezes earlier on mailbox write |
| `801A` | `A9 FF` | Failure path: LDA #$FF |
| `801C` | `8D 00 20` | STA $2000 → FAIL |
| `801F` | `DB` | STP |
| `FFFC` | `00 80` | Reset vector |

Key sampled cycles are 6/7: vector `00/80`; 8: opcode `18`; 15: operand `34`;
20: **write `$01:0000 = 46`**; 27: **read `$01:0000 = 46`**;
30: opcode BNE; 32: fetch `$00:8014`; 37: **write `$00:2000 = 01`**.
The full expected trace is asserted in
[cpu816.spec.js](../tests/static/cpu816.spec.js). No accumulator output is needed:
the actual store, readback, comparison, branch and mailbox expose execution.

To reproduce failures, select the ROM file and change the byte at `8005` from
`34` to `35`: the RTL now stores/reads `47`, takes BNE and writes `FF` at clock
38. Alternatively change opcode `D0` at `8012` to `F0` (BEQ), or XOR a stored
RAM byte with `01` in the memory file. Each produces an observed FAIL. Changing
only the store bank byte at `8009` to `02` writes unmapped bank 2 and leaves
bank 1 RAM zero, also failing. Change the reset-vector low byte to `19` to start
at STP: the board's **4096-clock RTL watchdog** reports FAIL. Restore the source
and compile to recover. Unsupported/looping programs can fail by timeout rather
than by a mailbox write; inspect trace and edited sources to distinguish them.

## Adapter, bounds and performance

The focused `cpu816` output contract requires `clk`, `reset`, unsigned 8-bit
`result`, 24-bit `trace_address`, 8-bit `trace_data` and 4-bit `trace_flags`, with
no extra ports. Flags are `{valid,VPA,VDA,write}`. The C++ adapter samples **up to
the first 128 valid bus cycles per request**, each as four unsigned 32-bit words:
`[cycle, address, data, flags]`. The runtime copies at most 2048 trace bytes per
reply. The UI displays the last 128 received rows; a long batch can omit later
bus cycles, so use Step for exact inspection. It is a bounded example adapter,
not a waveform recorder. Cycle numbering is one-based after reset, wrapping
at 2^32 in the adapter. The worker's general cycle count includes halted clocks.

The example totals **121,244 UTF-8 source bytes** across twelve files. The browser
source limit was increased only to **128 KiB** to fit this existing CPU; the
trusted-local limit remains 64 KiB. The 120-second compile deadline, 10-second
simulation watchdog, 64 MiB model memory cap and 16,384-clock maximum request
remain unchanged. Compilation memory still depends on the browser; peak memory
has not been measured. Other HDL limitations remain those in the README,
including two-state CXXRTL semantics for undefined values.

Local full-suite measurements on macOS 26.6.2 arm64, Playwright 1.64.1 desktop
browsers, static HTTP loopback under `/webrtl/`, fresh browser contexts (browser
processes are reused across tests and system caches may be warm):

| Browser | Compile including tool downloads | Active generated-model clocks/s | Wasm bytes |
| --- | ---: | ---: | ---: |
| Chromium | 6.3 s | about 2.3 million | 79,168 |
| Firefox | 5.4 s | about 2.3 million | 79,168 |

Compile time includes browser compiler startup, downloads from the local static
server, Yosys, Clang and fresh model initialization. It is not an Internet
download estimate. Throughput measures repeated reset + 37-clock executions to
PASS in the newly generated Wasm, including RAM reset and trace capture,
excluding UI/worker round trips. No halted clocks are counted. The automated
smoke test reports fresh timing/size JSON and attaches it to Playwright results.
The UI deliberately targets only 10,000 clocks/s; rendering and worker messaging
add overhead. These measurements are not hardware or cross-device guarantees.

## Automated validation and required post-merge check

From the repository root, after `npm ci` and installing the Playwright browsers:

```sh
npm run build:demo
npx playwright test --config=playwright.static.config.js tests/static/cpu816.spec.js
npm run test:demo
```

The CPU suite observes newly generated valid Wasm and static-only GET requests,
checks the complete bus trace, steps and Run/Pause, resets at multiple execution
points and during Run, edits instructions/branch/RAM/vector/bank, checks timeout
and compiler recovery, and independently tests ROM protection, full 24-bit
decoding, inactive writes and RAM reset. The complete static suite also retains
the counter, two-file counter, #14 bus, video and audio regressions. All of these
are pre-merge checks; they do not establish live deployment success.

Validation recorded on 2026-10-29: **8 Python tests passed**, **28 static browser
tests passed** (14 each in Chromium/Firefox), and the final rebuilt UI passed
the CPU smoke test again in both browsers. Re-running the adaptation script
reproduced all nine adapted CPU files byte for byte. The trusted-local regression
was attempted on port 8875 because 8765 was occupied; it failed at native linking
with `pthread_getaffinity_np`, `sched_getcpu` and `pthread_setaffinity_np`
undefined. This is the README's existing Verilator 5.052 / Emscripten 6.0.13
toolchain incompatibility, also reproduced with a direct counter build. That
native check did **not** pass; the browser compiler uses the pinned YoWASP
toolchain and all static regressions above passed.
